## 1. 概述

### 1.1 文档目的

本文档为新闻资讯发布与推荐系统的开发、测试、运维团队提供系统实现、测试验收、部署运维的核心依据，**完全遵循 SRS 定义的所有需求约束**，明确系统架构设计、关键流程、非功能性要求及部署方案。

### 1.2 系统上下文

![系统上下文图](F:\CourseAssignment\私有云\2\系统上下文图.png)

图 1 系统上下文图

系统上下文说明：

- 普通用户：浏览新闻、发布评论（敏感词过滤）、点赞、查看同分类推荐；
- 管理员：新闻 CMS 管理、分类 / 标签维护、评论审核、新闻上下架；
- 系统边界：严格遵循 SRS，不含智能推荐、短视频、付费、多终端等扩展能力。

### 1.3 名词解释

| 专有术语     | 定义说明（对齐 SRS）                                    |
| ------------ | ------------------------------------------------------- |
| CMS          | 新闻内容管理系统，支持分类 / 标签 / 富文本发布 / 上下架 |
| Redis 计数器 | 基于 INCR/DECR 的原子计数，用于新闻阅读量、点赞数统计   |
| ZSET         | Redis 有序集合，存储用户**最近 100 条**浏览新闻 ID      |
| 缓存一致性   | 更新写库 + 主动清缓存，每 5 分钟定时批量回写计数数据    |
| JWT          | JSON Web Token，用于无状态登录认证与权限控制            |
| 逻辑删除     | 采用`is_deleted`字段标记删除，禁止物理删除业务数据      |
| 敏感词过滤   | 对用户评论、新闻内容做合规校验，拦截违规内容            |

### 2.2 架构决策（ADR）

| 决策 ID | 决策背景                     | 可选方案                | 最终结论（对齐 SRS）                                         |
| ------- | ---------------------------- | ----------------------- | ------------------------------------------------------------ |
| ADR-001 | 系统规模小、SRS 约束架构     | 微服务 / 分层单体       | 采用**分层单体架构**（Controller→Service→Mapper），模块低耦合 |
| ADR-002 | SRS 强制要求 4 类 Redis 缓存 | MySQL 索引 / Redis 缓存 | 引入 Redis，实现 SRS 指定全部缓存场景                        |
| ADR-003 | SRS 要求权限分离             | Session/JWT             | Spring Security + JWT，区分 USER/ADMIN 角色                  |
| ADR-004 | SRS 禁止物理删除             | 物理删除 / 逻辑删除     | 所有业务表增加`is_deleted`逻辑删除字段                       |

### 3.2 关键接口定义

| 接口名称 | 协议 / 地址               | 请求方法 | 核心约束（对齐 SRS）                 |
| -------- | ------------------------- | -------- | ------------------------------------ |
| 新闻发布 | /api/news/publish         | POST     | 仅管理员、富文本 XSS 过滤、标题唯一  |
| 新闻详情 | /api/news/detail/{newsId} | GET      | 缓存优先、阅读量 + 1、返回同分类推荐 |
| 评论审核 | /api/comment/audit        | POST     | 仅管理员、修改审核状态               |
| 计数同步 | /api/news/count/sync      | POST     | 每 5 分钟批量回写 MySQL              |

### 3.3 扩展性设计

1. 数据库：新闻表按`create_time`预留分表规则，支持后续分库分表；
2. 服务层：无状态设计，支持水平扩展，适配高并发；
3. 推荐层：预留接口，支持后续替换为个性化推荐算法；
4. 接口层：全 RESTful 规范，支持后续第三方集成。

## 4. 非功能性设计

### 4.1 可用性设计

- **目标**：系统可用性≥99.9%，故障恢复≤30 分钟，数据丢失≤5 分钟；
- **措施**：多实例部署、Redis 故障降级直连 MySQL、MySQL 主从复制、Redis RDB+AOF 持久化。

### 4.2 性能设计

| 接口            | 平均响应时间 | 缓存命中率 | 并发要求            |
| --------------- | ------------ | ---------- | ------------------- |
| 首页新闻列表    | ≤200ms       | ≥90%       | ≥500 并发、QPS≥1000 |
| 新闻详情        | ≤100ms       | ≥95%       | ≥300 并发           |
| 阅读 / 点赞计数 | ≤50ms        | -          | ≥1000 并发          |

- **措施**：本地缓存 + Redis 分布式缓存、5 分钟异步批量回写、数据库联合索引、前端懒加载。

### 4.3 安全设计

1. **认证授权**：JWT 令牌 2 小时过期，BCrypt 加密密码，`@PreAuthorize`校验角色；
2. **注入防护**：MyBatis-Plus 预编译防 SQL 注入，富文本 XSS 过滤；
3. **攻击防护**：CSRF 防护、接口限流、防重放、IP 访问限制；
4. **内容安全**：评论敏感词过滤，新闻内容合规校验；
5. **审计日志**：操作日志不可篡改，留存≥6 个月。

## 5. 数据设计

### 5.1 核心数据模型

#### 5.1.1 系统用户表（sys_user）

| 字段名      | 类型         | 约束            |
| ----------- | ------------ | --------------- |
| id          | BIGINT       | 主键            |
| username    | VARCHAR(20)  | 唯一索引        |
| password    | VARCHAR(100) | BCrypt 加密     |
| role_id     | BIGINT       | 关联角色表      |
| status      | TINYINT      | 1 正常 / 0 禁用 |
| create_time | DATETIME     | -               |
| is_deleted  | TINYINT      | 逻辑删除        |

#### 5.1.2 系统角色表（sys_role）

| 字段名    | 类型        | 约束              |
| --------- | ----------- | ----------------- |
| id        | BIGINT      | 主键              |
| role_name | VARCHAR(20) | 普通用户 / 管理员 |
| role_code | VARCHAR(10) | USER/ADMIN        |

#### 5.1.3 新闻信息表（news_info）

| 字段名         | 类型        | 约束            |
| -------------- | ----------- | --------------- |
| id             | BIGINT      | 主键            |
| title          | VARCHAR(50) | 唯一索引        |
| category_id    | BIGINT      | 分类外键        |
| content        | LONGTEXT    | 富文本          |
| publish_status | TINYINT     | 0 草稿 / 1 发布 |
| shelf_status   | TINYINT     | 1 上架 / 0 下架 |
| is_deleted     | TINYINT     | 逻辑删除        |

#### 5.1.4 新闻统计量表（news_statistics）

| 字段名     | 类型     | 约束     |
| ---------- | -------- | -------- |
| id         | BIGINT   | 主键     |
| news_id    | BIGINT   | 唯一索引 |
| read_count | BIGINT   | 阅读量   |
| like_count | BIGINT   | 点赞数   |
| sync_time  | DATETIME | 同步时间 |

#### 5.1.5 其他核心表

- 新闻分类表（news_category）、新闻标签表（news_tag）、新闻 - 标签关联表（news_news_tag）
- 新闻评论表（news_comment）、新闻点赞表（news_like）、用户浏览记录表（user_browse_record）

### 5.2 存储与缓存方案

| 缓存 Key                     | 数据结构 | 过期时间 | 规则说明            |
| ---------------------------- | -------- | -------- | ------------------- |
| news:detail:{newsId}         | String   | 2 小时   | 新闻详情缓存        |
| news:view:count:{newsId}     | String   | 永久     | 阅读量计数器        |
| news:like:count:{newsId}     | String   | 永久     | 点赞数计数器        |
| news:home:list:{page}:{size} | String   | 1 小时   | 首页分页列表        |
| user:browse:history:{userId} | ZSET     | 7 天     | 最近 100 条浏览记录 |

- **一致性策略**：新闻更新→清除对应缓存；计数每 5 分钟批量回写；服务关闭强制全量同步。

### 6.2 资源预估

| 资源类型     | 配置规格          | 数量      | 用途                   |
| ------------ | ----------------- | --------- | ---------------------- |
| 应用服务器   | 4 核 8G、50G SSD  | 2         | 后端服务、负载均衡     |

3. **监控**：JVM 监控、MySQL 慢查询、Redis 命中率、服务健康检查。
