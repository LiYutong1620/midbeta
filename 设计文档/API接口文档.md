## 2. 通用说明

### 2.1 基础信息

|    项    |            取值            |          说明           |
| :------: | :------------------------: | :---------------------: |
| 基础 URL | https://api.example.com/v1 |    生产环境基础地址     |
| 字符编码 |           UTF-8            | 所有请求 / 响应统一编码 |
| 通信协议 |     HTTPS（TLS 1.2+）      |  生产环境强制加密传输   |
| 超时时间 |           30 秒            |  所有接口默认超时时间   |

### 2.2 请求 / 响应规范

#### 2.2.1 请求头规范

|  请求头名称   | 必填 |            取值示例            |                       说明                       |
| :-----------: | :--: | :----------------------------: | :----------------------------------------------: |
| Content-Type  |  是  |        application/json        | 接口请求体格式（文件上传为 multipart/form-data） |
| Authorization |  否  | Bearer eyJhbGciOiJIUzI1NiJ9... |      登录后携带的 JWT 凭证，非公开接口必填       |
|  Request-Id   |  否  |      req-1234567890abcdef      |            请求唯一标识，用于问题追踪            |

#### 2.2.2 响应格式规范

所有接口响应采用统一 JSON 结构，字段说明如下：

```
{
  "code": "SUCCESS",          // 业务错误码（SUCCESS为成功）
  "message": "操作成功",      // 提示信息（异常时为错误说明）
  "data": {},                 // 业务数据（成功时返回，异常时为null）
  "timestamp": 1710000000000, // 响应时间戳（毫秒）
  "requestId": "req-123456"   // 请求唯一标识（与请求头一致）
}
```

## 3. 接口详情

### 3.1 用户与权限模块

#### 3.1.1 用户注册接口

##### 接口定义

- 功能描述：普通用户账号注册，完成合法性校验与密码 BCrypt 加密存储
- 请求 URL：/api/user/register
- 请求方法：POST

##### 请求参数（JSON）

|     参数名      |  类型  | 必填 |    示例    |                  说明                   |
| :-------------: | :----: | :--: | :--------: | :-------------------------------------: |
|    username     | String |  是  | test_user  | 4-20 位字母、数字、下划线组合，全局唯一 |
|    password     | String |  是  | Test123456 |    6-20 位字符，需同时包含字母与数字    |
| confirmPassword | String |  是  | Test123456 |          与 password 完全一致           |

##### 成功响应示例

```
{
  "code": "SUCCESS",
  "message": "注册成功，请登录",
  "data": {
    "userId": 10001,
    "username": "test_user",
    "role": "USER"
  },
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

##### 异常响应示例

- 参数缺失（password）：

```
{
  "code": "VALIDATE-001",
  "message": "参数缺失：password",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

- 用户名已存在：

```
{
  "code": "USER-001",
  "message": "用户名已存在",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

- 密码格式错误：

```
{
  "code": "USER-002",
  "message": "密码格式错误（需包含字母+数字）",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

##### 非功能性说明

- 限流规则：单 IP 每分钟最多 5 次注册请求
- 幂等性：用户名唯一索引保证，重复提交不会创建重复账号
- 数据校验：用户名 / 密码格式由后端正则校验（前端仅做辅助校验）

#### 3.1.2 用户登录接口

##### 接口定义

- 功能描述：用户账号密码登录，校验通过后生成 JWT 凭证
- 请求 URL：/api/user/login
- 请求方法：POST

##### 请求参数（JSON）

|  参数名  |  类型  | 必填 |    示例    |      说明      |
| :------: | :----: | :--: | :--------: | :------------: |
| username | String |  是  | test_user  | 已注册的用户名 |
| password | String |  是  | Test123456 |    用户密码    |

##### 成功响应示例

```
{
  "code": "SUCCESS",
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEwMDAxLCJ1c2VybmFtZSI6InRlc3RfdXNlciIsInJvbGUiOiJVU0VSIiwiZXhwIjoxNzEwMDg2NDAwfQ.xxxx",
    "expireTime": 1710086400000,
    "userInfo": {
      "userId": 10001,
      "username": "test_user",
      "nickname": "测试用户",
      "role": "USER"
    }
  },
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

##### 异常响应示例

- 用户名不存在：

```
{
  "code": "USER-004",
  "message": "用户名不存在",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

- 密码错误：

```
{
  "code": "USER-005",
  "message": "密码错误",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

##### 非功能性说明

- 限流规则：单用户 / IP 每分钟最多 10 次登录请求，连续 5 次失败则封禁 10 分钟

- 幂等性：登录操作无副作用，重复提交不会生成多份凭证

- JWT 规则：

  - 加密算法：HS256
  - 载荷字段：userId、username、role、exp（过期时间，2 小时）
  - 刷新机制：凭证过期前 30 分钟可调用刷新接口（/api/user/refresh-token）获取新凭证

#### 3.2.2 发布新闻接口

##### 接口定义

- 请求 URL：/api/cms/news/publish
- 请求方法：POST
- 权限要求：ADMIN 角色

##### 请求头

|  请求头名称   | 必填 |            取值示例            |
| :-----------: | :--: | :----------------------------: |
| Authorization |  是  | Bearer eyJhbGciOiJIUzI1NiJ9... |

##### 请求参数（JSON）

|    参数名     |  类型  | 必填 |             示例              |               说明               |

|  categoryId   |  Long  |  是  |              101              |         已启用的分类 ID          |
|    tagIds     | Array  |  否  |         [1001, 1002]          |   最多关联 5 个已存在的标签 ID   |
|   coverUrl    | String |  否  | https://example.com/cover.jpg | 封面 URL，jpg/png 格式，大小≤5MB |
|    content    | String |  是  |        <p>正文内容</p>        |    富文本内容，自动 XSS 过滤     |
| publishStatus |  Int   |  否  |               1               |  0 - 草稿，1 - 正式发布，默认 0  |

##### 成功响应示例

```
{
  "code": "SUCCESS",
  "message": "新闻发布成功",
```

```
{
  "code": "VALIDATE-002",

  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

- 新闻标题已存在：

```
{
  "code": "NEWS-001",
  "message": "新闻标题已存在",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

- 封面图片格式错误：

```
{
  "code": "NEWS-003",
  "message": "封面图片格式错误（仅支持jpg/png）",
  "data": null,
  "timestamp": 1710000000000,
  "requestId": "req-123456"

```

##### 非功能性说明

- 限流规则：管理员账号每分钟最多 10 次新闻发布 / 编辑请求

- 幂等性：新闻标题唯一索引保证，重复提交不会创建重复新闻

  - 富文本：自动过滤<script>、onclick 等 XSS 风险标签
  - 封面 URL：校验格式与大小，支持 CDN 域名白名单

### 3.6 系统配置模块

#### 3.6.1 修改系统配置接口

##### 接口定义

- 功能描述：管理员修改系统配置参数，敏感配置需签名验证
- 请求 URL：/api/cms/config/edit
- 请求方法：PUT
- 权限要求：ADMIN 角色

##### 请求头

|  请求头名称   | 必填 |            取值示例             |                   说明                   |
| :-----------: | :--: | :-----------------------------: | :--------------------------------------: |
| Authorization |  是  | Bearer eyJhbGciOiJIUzI1NiJ9...  |                 JWT 凭证                 |
|     Sign      |  是  | md5(configKey+timestamp+secret) | 签名（仅修改敏感配置时必填，如系统开关） |

##### 请求参数（JSON）

|   参数名    |  类型  | 必填 |          示例          |               说明                |
| :---------: | :----: | :--: | :--------------------: | :-------------------------------: |
|  configKey  | String |  是  |   news_max_tag_count   |        配置键（全局唯一）         |
| configValue | String |  是  |           8            |              配置值               |
| configType  | String |  否  |         system         | 配置类型：system/frontend/backend |
|   remark    | String |  否  | 调整单篇新闻最大标签数 |             配置说明              |

##### 成功响应示例

```
{
  "code": "SUCCESS",
  "message": "配置修改成功",
  "data": {
    "configKey": "news_max_tag_count",
    "configValue": "8",
    "updateTime": "2026-03-24 11:00:00"
  },
  "timestamp": 1710000000000,
  "requestId": "req-123456"
}
```

##### 非功能性说明

- 敏感接口加密：

  - 签名规则：Sign = MD5 (configKey + timestamp + 管理员 secret)
  - secret：每个管理员独立生成，定期更换
  - timestamp：请求时间戳，误差≤5 分钟

  

- 操作审计：所有配置修改记录操作日志（操作人、时间、IP、修改前后值）

- 幂等性：基于 configKey 做幂等，重复提交不会重复修改

## 4. 非功能性说明补充

### 4.1 接口限流 / 熔断规则

|   接口类型   |           限流规则           |                熔断规则                |
| :----------: | :--------------------------: | :------------------------------------: |
|   公开接口   |    单 IP 每分钟≤60 次请求    |     错误率≥50% 时熔断，30 秒后恢复     |
| 用户操作接口 |    单用户每分钟≤20 次请求    |   连续 10 次失败后熔断，5 分钟后恢复   |
|  管理员接口  |   单管理员每分钟≤30 次请求   |    错误率≥30% 时熔断，1 分钟后恢复     |
| 核心计数接口 | 单新闻每分钟≤1000 次计数请求 | Redis 故障时降级为本地计数，恢复后同步 |

### 4.2 接口幂等性说明

| 接口场景 |               幂等实现方式               |           适用范围           |
| :------: | :--------------------------------------: | :--------------------------: |
| 数据创建 | 唯一索引（用户名 / 分类名称 / 新闻标题） | 注册、新增分类 / 标签 / 新闻 |
| 数据更新 |          乐观锁（version 字段）          |    编辑新闻 / 分类 / 配置    |
| 计数操作 |       Redis 原子命令（INCR/DECR）        |     阅读量 / 点赞数统计      |
| 评论发布 |       请求 ID + 用户 ID + 新闻 ID        |       避免重复发布评论       |

### 4.3 数据校验详细规则

|  校验字段  |                   校验规则                   |      错误码       |
| :--------: | :------------------------------------------: | :---------------: |
|  分类 ID   |      必须为正整数，关联分类表存在且启用      |   CATEGORY-003    |
|  新闻 ID   |     必须为正整数，关联新闻表存在且未删除     |     NEWS-002      |
|  封面 URL  |   格式：^https?://.*.(jpg\|png)$，大小≤5MB   | NEWS-003/NEWS-004 |
| 富文本内容 | 过滤<script>/onclick 等 XSS 标签，敏感词过滤 |    COMMENT-001    |
|  分页参数  |           page≥1，pageSize≥1 且≤50           | VALIDATE-001/002  |

### 4.4 缓存策略详细说明

|   缓存场景   |          缓存 Key 格式           | 过期时间 |                   更新机制                    |
| :----------: | :------------------------------: | :------: | :-------------------------------------------: |
|   新闻详情   |       news:detail:{newsId}       |  2 小时  |          编辑 / 上下架 / 删除时清除           |
|   首页列表   | news:home:list:{page}:{pageSize} |  1 小时  |  发布 / 编辑 / 上下架新闻时清除所有首页缓存   |
|  阅读量计数  |     news:view:count:{newsId}     |   永久   | 每 5 分钟批量同步到 MySQL，服务关闭时强制同步 |
|  点赞数计数  |     news:like:count:{newsId}     |   永久   |                 同阅读量计数                  |
| 用户浏览历史 |   user:browse:history:{userId}   |   7 天   |           超出 100 条时删除最早记录           |

### 4.5 敏感接口加密 / 签名说明

|   敏感接口   |            加密 / 签名方式             |                安全要求                |
| :----------: | :------------------------------------: | :------------------------------------: |
| 系统配置修改 | MD5 签名（configKey+timestamp+secret） | secret 定期更换，timestamp 误差≤5 分钟 |
|  管理员登录  |         HTTPS+BCrypt 密码加密          |       密码传输加密，存储加盐加密       |
| 敏感数据查询 |        数据脱敏（手机号 / IP）         |   仅返回脱敏后数据，原始数据不可查询   |
